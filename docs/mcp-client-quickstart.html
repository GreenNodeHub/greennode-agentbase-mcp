Client Quick Start

Connect any MCP client to AgentBase in under five minutes.

The AgentBase MCP gateway exposes your AgentBase services — runtimes, gateways, policies, identities, memory, container registry — through three meta-tools. Pick your client below, copy the config, and go. Two ways to connect: local stdio (run the server on your machine) or remote HTTP (use the gateway endpoint).

01Prerequisites & installation

Two things you need before any client.

A bearer token, and (for the local stdio path) the server running on your machine. The remote HTTP path skips the local install entirely.

The bearer token

Every connection authenticates with an AgentBase bearer token. Get one from your IAM service account (client id + secret → token). You'll set it as an environment variable named GREENNODE_MCP_TOKEN (or any name you configure via TOKEN_ENV).

⚠
Treat the token like a password. Never commit it to git or paste it into shared config. All client configs below reference it as ${GREENNODE_MCP_TOKEN} so the value stays in your environment, not the file.

Choose your connection path

⎘
Local stdio — the client spawns the server as a subprocess. You clone the repo and run npx tsx src/index.ts. Used by Claude Desktop, Claude Code, Cursor, Windsurf, Cline, Roo Code. Best for development and when you control the machine.
☁
Remote HTTP — the client talks to the AgentBase MCP gateway over HTTPS (IAM-authenticated front door). No local install. Used by Claude.ai (web) and any client that supports Streamable HTTP. Best when you can't or don't want to run the server locally.

For the local stdio path: clone & install

# clone and install dependencies (Node >= 20)
git clone <repo-url> greennode-agentbase-mcp
cd greennode-agentbase-mcp
npm install

# set your token in the environment (do this in your shell profile too)
export GREENNODE_MCP_TOKEN="<your-token>"

# sanity check — should print a startup banner and wait for input
npx tsx src/index.ts
# → greennode-agentbase-mcp stdio  (Ctrl-C to exit)
ℹ
Why clone for stdio? The stdio server loads a bundled operation registry (registry.generated.json) at startup. It ships with the repo, so the local server needs the checkout. The remote HTTP endpoint already has it baked into the deployed image — no clone needed.

Token rotation

The GREENNODE_MCP_TOKEN is an IAM service-account JWT — short-lived (≈30 min). The same token works on the stdio path and at the gateway. The repo ships a helper that mints (or returns a cached, not-yet-expired) token:

# mints via grant_type=client_credentials, caches in .agentbase/token_cache,
# reuses the cache until 60s before exp. Pass --force to mint fresh.
export GREENNODE_MCP_TOKEN=$(bash .claude/skills/agentbase/scripts/get_token.sh)

The helper needs your IAM client credentials — GREENNODE_CLIENT_ID + GREENNODE_CLIENT_SECRET in the env, or a .greennode.json in the repo root. That's the minting secret, not the token itself.

↻
The stdio rotation wrapper. stdio clients read the token at spawn and hold it static, so a long-running server can outlive the token. The repo ships scripts/mcp-launch.sh — it mints a fresh token, then execs the server. Point your client at it instead of npx tsx and every relaunch rotates automatically: 
"command": "bash",
"args": ["/ABSOLUTE/PATH/TO/greennode-agentbase-mcp/scripts/mcp-launch.sh"]
Each client section below shows its relaunch lever (quit the app, /mcp reconnect, restart MCP). If you only have a static token and no client secret, skip the wrapper and just re-export GREENNODE_MCP_TOKEN before relaunching.
02Claude Desktop (stdio) — start here

The widest reach. Edit one JSON file.

Claude Desktop (the macOS / Windows app) speaks MCP over stdio. You point it at a command and it spawns the server for you. This is the recommended starting point — no terminal, no long-running process to manage.

Steps

  1. Complete §01 — clone the repo, npm install, and export GREENNODE_MCP_TOKEN.
  2. Open (or create) the Claude Desktop MCP config: 
    # macOS
~/Library/Application Support/Claude/claude_desktop_config.json

# Windows
%APPDATA%\Claude\claude_desktop_config.json
  3. Add the agentbase server entry below. Use absolute paths for the repo and npx — Claude Desktop needs them.
  4. Quit Claude Desktop fully (not just close the window) and relaunch.
  5. Start a new chat. You should see agentbase listed under connected MCP servers. Try: "List my agent runtimes."

Config

{
  "mcpServers": {
    "agentbase": {
      "command": "npx",
      "args": ["tsx", "/ABSOLUTE/PATH/TO/greennode-agentbase-mcp/src/index.ts"],
      "cwd": "/ABSOLUTE/PATH/TO/greennode-agentbase-mcp",
      "env": {
        "GREENNODE_MCP_TOKEN": "<your-token>"
      }
    }
  }
}
⚠
Use absolute paths. Claude Desktop launches from a different working directory than your shell. Replace /ABSOLUTE/PATH/TO/greennode-agentbase-mcp with the real path (e.g. /Users/you/src/greennode-agentbase-mcp).
✓
It worked when a new chat shows the server connected, and asking "what AgentBase services are available?" calls the list_servers tool and returns the six services.
↻
Rotating the token. Claude Desktop reads GREENNODE_MCP_TOKEN when it spawns the server and holds it static. To rotate: quit Claude Desktop fully and relaunch — it re-spawns the server with a fresh token. For auto-rotation at every launch, swap npx tsx for the wrapper from §01 ("command": "bash", "args": ["…/scripts/mcp-launch.sh"]); the wrapper needs GREENNODE_CLIENT_ID + GREENNODE_CLIENT_SECRET on the machine.
03Claude Code (stdio) — for developers

The natural next step if you live in the terminal.

Claude Code is the CLI. It reads MCP servers from ~/.claude.json (or a project .mcp.json) and connects on startup. Same stdio mechanism as Claude Desktop, configured once for all your sessions.

Steps

  1. Complete §01.
  2. Add the server. Easiest way — run this in the repo directory: 
    claude mcp add agentbase \
  -e GREENNODE_MCP_TOKEN="<your-token>" \
  -- npx tsx src/index.ts
    Or edit ~/.claude.json directly — add an entry under mcpServers in the relevant project (or the top-level).
  3. Restart Claude Code (or start it in this repo).
  4. Verify the server is connected: run /mcp inside a session. agentbase should show as connected with 3 tools.

Config (in ~/.claude.json)

{
  "mcpServers": {
    "agentbase": {
      "type": "stdio",
      "command": "npx",
      "args": ["tsx", "src/index.ts"],
      "cwd": "/ABSOLUTE/PATH/TO/greennode-agentbase-mcp",
      "env": {
        "GREENNODE_MCP_TOKEN": "<your-token>"
      }
    }
  }
}
→
Repo-relative path works here. Claude Code respects the cwd field, so src/index.ts resolves correctly. Still pin cwd to an absolute path so the server works from any session.
ℹ
Project vs user scope. Put the entry under projects["<repo-path>"].mcpServers to scope it to this repo, or under the top-level mcpServers for every session. The claude mcp add command scopes to the current project by default.
↻
Rotating the token. Claude Code holds the token static after spawn. With the §01 wrapper as your command, running /mcp and reconnecting the agentbase server re-spawns the wrapper and mints a fresh token — no full relaunch needed. Without the wrapper, re-mint (export GREENNODE_MCP_TOKEN=$(bash .claude/skills/agentbase/scripts/get_token.sh)) and relaunch Claude Code.

05Claude.ai (HTTP Streamable) — remote

No local install — use the gateway endpoint.

For Claude.ai (the web app) and any client that supports Streamable HTTP, point at the AgentBase MCP gateway — the IAM-authenticated front door that proxies the runtime. No local install; you just supply the URL and token.

Endpoint https://gw-agentbase-mcp-53461.agentbase-gateway.aiplatform.vngcloud.vn/agentbase_mcp/mcp

Steps

  1. Get your GREENNODE_MCP_TOKEN (you do not need to clone the repo for this path).
  2. In your client's MCP settings, add an HTTP server with the URL and a Bearer auth header.
  3. Connect and verify with a "list my agent runtimes" prompt.

Config (Claude Code, HTTP entry)

{
  "mcpServers": {
    "agentbase": {
      "type": "http",
      "url": "https://gw-agentbase-mcp-53461.agentbase-gateway.aiplatform.vngcloud.vn/agentbase_mcp/mcp",
      "headers": {
        "Authorization": "Bearer ${GREENNODE_MCP_TOKEN}"
      }
    }
  }
}
ℹ
Claude.ai web connector. Claude.ai's web UI adds remote MCP servers via Settings → Connectors → Add custom connector. Give it the gateway URL and the Bearer header. The connector runs server-side, so your token is stored with Anthropic — use a token scoped for this purpose if that matters to you.
⚠
Token TTL. The GREENNODE_MCP_TOKEN is an IAM service-account JWT (≈30 min). The gateway validates it on the way in, so the same token works here and on the stdio path. For a long-running remote connector, expect to refresh periodically — failed calls with 401 mean the token expired.
→
Direct-endpoint fallback. Prefer the gateway — it enforces IAM inbound auth and centralizes access logging. If you need an always-on client that can't refresh short-lived JWTs, the underlying runtime also accepts a long-lived access token at https://endpoint-556ba588-2efe-4b68-8799-6645bae86e4d.agentbase-runtime.aiplatform.vngcloud.vn/mcp with the same Authorization: Bearer header. That path skips the gateway's auth and audit layer.
↻
Rotating the token. The web connector stores the Bearer with Anthropic and runs server-side — there's no process of yours on a schedule, so it can't self-rotate. Three options: (1) manual — re-mint and re-paste the token into the connector on 401 (fine for short sessions); (2) refresh proxy — run a small HTTPS endpoint that mints per request and forwards to the gateway, and point the connector at it (the proxy becomes your trust boundary — restrict inbound to it); (3) long-lived token on the direct endpoint — the fallback above: no rotation, but no gateway audit either.
06Agent frameworks — programmatic

One pick: the MCP TypeScript SDK.

If you're building an agent in code (not using a chat client), connect to the gateway with the official MCP client SDK. The SDK handles the JSON-RPC handshake, tool discovery, and calls. Here's the TypeScript client over stdio — the same pattern works in Python.

TypeScript (stdio)

import { Client } from "@modelcontextprotocol/sdk/client/index.js";
import { StdioClientTransport } from "@modelcontextprotocol/sdk/client/stdio.js";

const transport = new StdioClientTransport({
  command: "npx",
  args: ["tsx", "src/index.ts"],
  cwd: "/path/to/greennode-agentbase-mcp",
  env: { ...process.env, GREENNODE_MCP_TOKEN: process.env.GREENNODE_MCP_TOKEN! },
});

const client = new Client(
  { name: "my-agent", version: "0.1.0" },
  { capabilities: {} },
);
await client.connect(transport);

// 1. orient
const { tools } = await client.listTools();
console.log(tools.map(t => t.name)); // ["list_servers","search_tools","execute"]

// 2. discover the operation you need
const search = await client.callTool({
  name: "search_tools",
  arguments: { query: "list agent runtimes", limit: 5 },
});

// 3. execute it (id comes from the search hits — real ids mirror the
//    upstream spec's operationId, so e.g. listing runtimes is "runtime.list_1")
const result = await client.callTool({
  name: "execute",
  arguments: { id: "runtime.list_1", args: {} },
});
→
The three-step pattern. Every interaction is list_servers (orient) → search_tools (discover) → execute (run). You can skip list_servers once you know the service you want. Always take the id from search_tools — operation ids mirror the upstream OpenAPI spec's operationId, so they're not always pretty (runtime.list_1, runtime.get, runtime.listEndpoints …) and can shift between spec versions. Pass fields to execute for a JMESPath projection that shrinks large responses.

Python (stdio) — same shape

from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

params = StdioServerParameters(
    command="npx",
    args=["tsx", "src/index.ts"],
    cwd="/path/to/greennode-agentbase-mcp",
    env={"GREENNODE_MCP_TOKEN": token},
)

async with stdio_client(params) as (read, write):
    async with ClientSession(read, write) as session:
        await session.initialize()
        tools = await session.list_tools()
        hits = await session.call_tool("search_tools", {"query": "list runtimes"})
        result = await session.call_tool("execute", {"id": "runtime.list_1", "args": {}})

Rotating the token (in code)

You own the loop, so mint, cache, and refresh explicitly. Refresh ~5 min before the JWT exp and retry once on 401. For stdio, set the env before spawning; for HTTP, set Authorization per call. Decode the JWT payload yourself (no extra deps) as shown, or use a library — the logic is the same.

let cached: { token: string; exp: number } | undefined;

async function freshToken(): Promise<string> {
  if (cached && cached.exp > Date.now() / 1000 + 300) return cached.token;
  const res = await fetch("https://iam.api.vngcloud.vn/accounts-api/v2/auth/token", {
    method: "POST",
    headers: {
      "Authorization": "Basic " + Buffer.from(
        `${process.env.GREENNODE_CLIENT_ID}:${process.env.GREENNODE_CLIENT_SECRET}`
      ).toString("base64"),
      "Content-Type": "application/x-www-form-urlencoded",
    },
    body: "grant_type=client_credentials",
  });
  const { access_token } = await res.json();
  const seg = access_token.split(".")[1].replace(/-/g, "+").replace(/_/g, "/");
  const payload = JSON.parse(Buffer.from(seg, "base64").toString("utf8"));
  cached = { token: access_token, exp: payload.exp };
  return access_token;
}

// HTTP gateway: attach a fresh Bearer per call (refresh + 401-retry)
headers: { Authorization: `Bearer ${await freshToken()}` }
ℹ
Same primitive, in-process. This is exactly what .claude/skills/agentbase/scripts/get_token.sh does (mint → cache → expiry check with a safety margin), ported into your agent. For stdio, call it once and pass the result as GREENNODE_MCP_TOKEN to the spawn env; refresh by re-spawning. For Python, the same grant_type=client_credentials POST with requests.auth.HTTPBasicAuth and a time.time() > exp - 300 guard.
